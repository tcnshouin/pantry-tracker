# agent_notion — Design Spec
**Date:** 2026-04-20
**Project:** PlanifyPH Etsy Automation (n8n, Docker, localhost:5678)

## Overview
Automatically create a structured Notion template for each product processed by `agent_design_content`. The agent reads `pages_json` generated by the Design agent and builds a fully functional Notion page hierarchy using the Notion API.

## Trigger
Automatic — called via Execute Workflow node at the end of `agent_design_content`, after "Append to Content Queue" and "Mark design_complete" nodes. Receives `product_name` and `pages_json` as input parameters.

## Architecture

```
agent_design_content
  └── [existing nodes]
  └── Append to Content Queue
  └── Mark design_complete
  └── Execute agent_notion (async) ← new node

agent_notion
  └── Dispatcher Trigger (executeWorkflowTrigger)
  └── Parse pages_json
  └── Create product page under "Planify Templates" root
  └── Loop through pages (SplitInBatches, batch size 1)
        ├── tracker   → Create inline Notion database (content_elements as Text properties)
        ├── planner   → Create page with H2 + to-do checkboxes
        ├── reference → Create page with H2 + simple table
        ├── cover     → Create page with H1 + purpose subtitle + bullet list
        ├── divider   → Create page with H2 + divider block + bullet list
        └── journal   → Create page with H2 + toggle blocks
  └── Build done summary
  └── Telegram — Done (with Notion URL)
  └── Save notion_url to Content Queue
  └── On Workflow Error → Telegram error notification
```

## Notion Structure

```
📁 Planify Templates          ← root page, created manually once
  └── 📄 [product_name]       ← created per product
        └── [pages from pages_json, in order]
```

The "Planify Templates" root page is created **manually once** by the user in Notion, shared with the Planify integration, and its page ID is hardcoded in the workflow as a variable.

## Layout Type → Notion Block Mapping

| layout_type | Notion Output |
|---|---|
| `cover` | Page with H1 (name) + purpose as paragraph + content_elements as bulleted list |
| `divider` | Page with H2 (name) + horizontal divider block + content_elements as bulleted list |
| `planner` | Page with H2 (name) + purpose paragraph + content_elements as to-do checkboxes (one per element, unchecked) |
| `reference` | Page with H2 (name) + purpose paragraph + `simple_table` block: `table_width=2`, `has_column_header=true`, `has_row_header=false`. Row 1 = header cells ["Item", "Notes"]. One additional `table_row` per content_element: cell 1 = element text, cell 2 = empty string. |
| `tracker` | Child inline database of the product page, title = page name, one Text-type property per content_element string, no sample rows |
| `journal` | Page with H2 (name) + purpose paragraph + content_elements as toggle blocks (each toggle title = element text, body empty) |

## Data Flow

**Input (from agent_design_content):**
- `product_name` — string
- `pages_json` — JSON array (parsed from Content Queue)

**Notion API calls per run:**
1. `POST /v1/pages` — create product page under root
2. Per page in pages_json: `POST /v1/pages` (child page) or `POST /v1/databases` (tracker)
3. `PATCH /v1/pages/{id}` — append blocks to each page

**Output written back:**
- `notion_url` column in Content Queue → URL of the product's Notion page

## Error Handling

| Scenario | Handling |
|---|---|
| `pages_json` parse failure | Separate IF branch before the loop (not On Workflow Error). Writes to CS Log, then sends Telegram error via direct HTTP Request node: "❌ agent_notion: failed to parse pages_json for [product_name]". Workflow stops here. |
| Individual page creation fails | `onError: continueRegularOutput` on each Notion HTTP node. The done summary Code node counts total pages vs items processed to report "X of Y pages created". No per-name tracking. |
| Notion API auth failure | Uncaught → On Workflow Error node → Telegram: "❌ agent_notion failed: [error.message] — product: [product_name]" |
| Root page ID missing/empty | IF check at workflow start → separate Telegram HTTP node: "❌ agent_notion: root page ID not configured". Workflow stops here. |

**CS Log columns written on parse failure:** `agent` = "agent_notion", `product_name`, `error_type` = "parse_failure", `error_message`, `raw_response` = raw pages_json string, `timestamp`

**On Workflow Error node:** errorTrigger type, single HTTP POST to hardcoded Telegram sendMessage URL, message: `❌ agent_notion error\nProduct: [product_name]\nError: [error.message]`

## Credentials
- Notion API token stored in n8n credential: **"Planify Notion"**
- Root page ID ("Planify Templates") hardcoded as a Set node variable at workflow start

## notion_url Capture
- **Which URL:** the product root page URL (e.g. `https://notion.so/Product-Name-{id}`) — not child page URLs
- **How saved:** Google Sheets update node matching on `product_name` column, writing to `notion_url` column
- **When:** after the SplitInBatches loop completes (Output 0 path)
- `notion_url` column must be added to the Content Queue sheet before the workflow runs

## SplitInBatches Configuration
- Batch size: **1** (one page created per iteration)
- Output 0 = loop done → Build done summary → Telegram → Save notion_url
- Output 1 = inside loop → Switch on layout_type → Create Notion page/database

## Switch Node — layout_type Routing
Routes on `layout_type` with 6 named outputs: cover, divider, planner, reference, tracker, journal.
**Fallback (no match):** Switch output "fallback" → Code node that logs the unknown layout_type to CS Log (error_type = "unknown_layout_type") and continues to next loop iteration — no page is created, counted as a failed page in the summary.

## Google Sheets — notion_url Write
- Update mode, match column: `product_name`
- If **zero rows match**: log to CS Log (error_type = "notion_url_write_miss"), send Telegram warning, do not fail workflow
- If **multiple rows match**: n8n Google Sheets update node updates the first matching row only (default n8n behavior) — acceptable since product_name is unique by design in the Content Queue

## Constraints
- Notion API: 100 blocks max per request — each page is created individually (well within limit)
- SplitInBatches: Output 0 = done, Output 1 = inside loop
- All Telegram URLs hardcoded (no `$env.TELEGRAM_BOT_TOKEN` — denied in URL fields)
- `onError: continueRegularOutput` on all HTTP nodes to handle Docker DNS issues
